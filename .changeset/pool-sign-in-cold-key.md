`verifySignature` now accepts a signature from a pool's cold key, whose hash is the pool ID, whether or not the pool has a calidus key. It previously accepted the cold key only from a pool with no calidus key, and required the calidus key once one was registered. A signature from the pool's active calidus key is still accepted, except when that key is all zeros, which CIP-151 defines as a revocation: an all-zero key now matches no signature. A COSE signature made with the cold key must name the pool ID in its protected `address` header, and one made with the calidus key may name the pool ID or the calidus ID. `verifySignature` now also requires the pool to be registered, and returns `{ error: 'Pool is not registered' }` for a pool that is retired or was never registered, whichever key signed. A pool whose retirement certificate names an epoch that has not yet begun is still registered. The new `validatePool` makes the same check on its own, returning `true` for a registered pool and `false` for a retired or unknown one, and throws `ProviderError` when no provider can answer, as `verifySignature` does. `validatePool` and the new `PoolStatus` type are exported from the package root and from `@lerna-labs/ekklesia-helpers/cardano`. `CardanoProvider` gains a `fetchPoolStatus` method returning `PoolStatus`, and the Koios calidus key lookup now asks for the highest-nonce registration only.
